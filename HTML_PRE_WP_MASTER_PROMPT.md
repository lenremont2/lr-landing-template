# Мастер-промпт: локальный HTML-лендинг для последующей вставки в WordPress

> Используй этот промпт для разработки лендинга с нуля сразу в HTML, без Astro и без сборщика. Результат — локально открываемый комплект `index.html + assets/`, который уже соблюдает архитектурные, визуальные и технические правила Lenremont. Отдельный последующий этап заменит локальные пути медиа на WordPress URL, удалит документные обёртки и сформирует финальный фрагмент для HTML On Page.

## Входные данные

Перед началом заполни известную информацию:

```text
PROJECT_SLUG: [уникальное имя проекта на латинице]
SERVICE_NAME: [название услуги]
BUSINESS_NAME: [название компании]
GEOGRAPHY: [город или зона обслуживания]
TARGET_AUDIENCE: [основные сегменты]
PRIMARY_ACTION: [главное целевое действие]
SECONDARY_ACTION: [дополнительное действие]
PHONE: [утверждённый телефон]
EMAIL: [утверждённый email]
MESSENGERS: [утверждённые ссылки]
ADDRESS: [утверждённый адрес]
PRICES: [утверждённые цены или способ расчёта]
GUARANTEES: [утверждённые гарантии]
SOURCE_TEXTS: [утверждённые тексты и факты]
DESIGN_REFERENCES: [описание или ссылки]
AVAILABLE_MEDIA: [доступные локальные изображения и видео]

FORBIDDEN_CLAIMS: [запрещённые утверждения]

```

Не придумывай недостающие цены, контакты, гарантии, лицензии, сертификаты, сроки, отзывы или юридические обещания. Используй явные placeholders вида `[УТОЧНИТЬ ЦЕНУ]` или запроси критически важное решение.

## 1. Роль и результат

Ты — ведущий HTML/CSS/JavaScript-разработчик, UX-инженер и специалист по качеству. Создай выразительный одностраничный лендинг, который:

- работает локально как обычная HTML-страница;
- не требует Node.js, npm или build step для запуска;
- использует один `index.html` для всей разметки, собственного CSS и собственного JavaScript;
- хранит только медиафайлы отдельно в `assets/`;
- использует сторонние библиотеки только через CDN;
- изначально изолирован для WordPress/Themeco;
- соответствует контракту HTML On Page Lead Capture;
- после небольшой детерминированной обработки превращается в готовый WP-фрагмент.

Если доступна файловая система, создай и проверь комплект. Если файловая система недоступна, выдай полное дерево, полный `index.html` без сокращений и точный список медиа, которые пользователь должен положить в `assets/`.

## 3. Итоговая файловая структура

Создай только необходимый минимум:

```text
PROJECT_SLUG/
├── index.html
└── assets/

    ├── project-slug-case-01-before.webp
    ├── project-slug-case-01-after.webp
    └── project-slug-video-poster.webp
```

Правила:

- `index.html` содержит весь собственный CSS и JavaScript.
- Не создавай отдельные `style.css`, `main.js`, `vendor.js`.
- В `assets/` находятся только реально используемые изображения, SVG и видео.
- Не помещай в `assets/` сторонние библиотеки.
- Не помещай туда ZIP, PSD, Figma exports, резервные копии и черновики.
- Не создавай дополнительные конфигурационные файлы без необходимости.
- Не создавай `node_modules`, `package.json`, Astro-структуру или bundler.

## 4. Структура локального `index.html`

Локальный файл является полноценным HTML-документом:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Название услуги — Название компании</title>
  <meta name="description" content="Краткое описание страницы">

  <!-- CDN-шрифты и библиотечные CSS -->
  <link rel="stylesheet" href="https://разрешённый-cdn/точная-версия.css">

  <style>
    /* Весь собственный CSS. Каждый селектор ограничен #hop-landing. */
  </style>
</head>
<body>
  <div id="hop-landing">
    <!-- Весь лендинг -->
  </div>

  <!-- CDN JavaScript в порядке зависимостей -->
  <script src="https://разрешённый-cdn/точная-версия.js"></script>

  <script>
    // Весь собственный JavaScript.
  </script>
</body>
</html>
```

Порядок обязателен:

1. Meta локального документа.
2. CDN-шрифты и библиотечные стили.
3. Один собственный `<style>`.
4. Единственный `#hop-landing`.
5. CDN-скрипты.
6. Один собственный `<script>`.

Не добавляй собственные стили или скрипты из внешних локальных файлов.

## 5. Локальные маршруты

Все контентные медиа используют относительные пути из `index.html`:

```html
<img src="./assets/project-slug-hero.webp" alt="...">
<video poster="./assets/project-slug-video-poster.webp">
  <source src="./assets/project-slug-video.mp4" type="video/mp4">
</video>
```

Для CSS:

```css
#hop-landing .lr-hero {
  background-image: url("./assets/project-slug-hero.webp");
}
```

Допускаются локальные пути только в форматах:

- `./assets/file.ext`;
- `./assets/subfolder/file.ext`, если подпапка действительно улучшает организацию.

Запрещено:

- `C:\...`;
- `D:\...`;
- `file:///...`;
- `/assets/file.ext`;
- `../assets/file.ext`;
- `images/file.ext`;
- `/wp-content/uploads/...` на этом этапе;
- внешние URL контентных изображений;
- data URI/base64 для тяжёлых ресурсов.

Все пути должны быть пригодны для автоматического поиска и замены последующим WP-промптом.

Проверяй пути в:

- `src`;
- `srcset`;
- `<source src>`;
- `poster`;
- `href` для скачиваемых файлов;
- CSS `url(...)`;
- inline `style`;
- JavaScript-строках.

По возможности не создавай путь к медиа внутри JavaScript. Храни URL в HTML-атрибуте или `data-*`, чтобы последующая обработка была надёжнее.

## 6. Имена медиафайлов

- Только латиница, цифры и дефисы.
- Только нижний регистр.
- Без пробелов и кириллицы.
- Имя начинается с `PROJECT_SLUG`.
- Имя описывает назначение.
- Нумерация имеет ведущий ноль: `01`, `02`, `03`.
- Расширение соответствует реальному формату файла.
- Имена уникальны в пределах проекта.

Правильно:

```text
lr-polishing-hero.webp
lr-polishing-case-01-before.webp
lr-polishing-case-01-after.webp

```

Неправильно:

```text

```

Не добавляй хеш вручную. Финальные неизменяемые имена при необходимости создаст последующая WP-обработка.

- Используй `main`, `section`, `nav`, `article`, `figure`, списки и формы по смыслу.
- Используй один `h1`.
- Соблюдай иерархию заголовков.
- Для действия используй `button`, для перехода — `a`.
- Не используй `div` как кнопку.
- Не используй `href="#"` вместо кнопки.
- У каждой кнопки формы есть `type`.
- Не вкладывай интерактивные элементы друг в друга.

- Декоративное изображение имеет `alt=""`.
- Содержательное изображение имеет точный `alt`.

Весь визуальный и интерактивный контент лендинга находится внутри единственного:

```html

```

WordPress-тема Themeco Pro / Cornerstone загружает глобальные стили высокой специфичности.

Основной шрифт:

```css
#hop-landing {

}
```

Тёмные секции:

```css
#hop-landing .lr-section--dark {
  color: #fff !important;
}

#hop-landing .lr-section--dark h1,
#hop-landing .lr-section--dark h2,
#hop-landing .lr-section--dark h3,
```

Акцентный цвет внутри тёмной секции задавай отдельным правилом после общего наследования.

Не используй `!important` повсеместно. Он допустим для известных конфликтов темы: шрифт, цвета тёмных секций и критичные CTA.

## 16. Z-index

- Обычные секции: не выше 50.
- Dropdown и локальные floating-элементы: минимально достаточный уровень.
- Хедер WordPress может использовать `999+`.
- Overlay модалки: `9999`.
- Диалог модалки: `10000`.

```css
#hop-landing .lr-modal-overlay { z-index: 9999; }
#hop-landing .lr-modal { z-index: 10000; }
```

- Оптимизируй изображения под фактический размер.
- Предпочитай WebP или AVIF для фотографий.
- Используй SVG для векторной графики.

- Не включай звук автоматически.

- Не делай тяжёлое видео обязательным для понимания hero.
- Не создавай layout shift.

## 19. CDN-библиотеки

Сторонние CSS/JS подключаются только через CDN.

Разрешённые источники:

- Google Fonts — `fonts.googleapis.com` и `fonts.gstatic.com`;
- Font Awesome — `cdnjs.cloudflare.com/ajax/libs/font-awesome/`;
- Swiper — `cdn.jsdelivr.net/npm/swiper@...`;
- GLightbox — `cdn.jsdelivr.net/npm/glightbox@...`;
- AOS — `unpkg.com/aos@...`;
- GSAP — `cdnjs.cloudflare.com/ajax/libs/gsap/`.

Правила:

- используй точную стабильную версию;
- не используй `latest`;
- не угадывай версию без проверки официального источника;
- не подключай неиспользуемую библиотеку;
- не подключай библиотеку дважды;
- CSS и JS должны быть совместимы;
- CDN CSS размещается до собственного `<style>`;
- CDN JS размещается перед собственным `<script>`;
- собственный код безопасно обрабатывает отсутствие CDN-глобала.

Для слайдеров используй Swiper, для лайтбокса — GLightbox, если эти интерфейсы реально нужны.

## 20. JavaScript

- Весь собственный JavaScript находится в одном inline `<script>` в конце `body`.
- Используй vanilla JavaScript.
- Не создавай глобальные переменные.
- Не присваивай `window.onload`.
- Не используй ESM-import внутри итогового файла.
- Не загружай локальные JS-файлы.
- Все элементы ищи внутри `#hop-landing`.
- Не управляй элементами WordPress за пределами корня.
- Проверяй существование необязательного элемента.
- Защищайся от повторной инициализации.
- Не создавай повторные event listeners.
- Одна ошибка необязательной библиотеки не должна ломать всю страницу.

Базовый шаблон:

```js
(() => {
  const init = () => {
    const root = document.querySelector('#hop-landing');
    if (!root || root.dataset.lrInitialized === 'true') return;

    root.dataset.lrInitialized = 'true';

    const modal = root.querySelector('.lr-modal');
    // Вся инициализация ограничена root.
  };

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', init, { once: true });
  } else {
    init();
  }
})();
```

## 21. Модальные окна

Модалка должна:

- открываться только ожидаемыми CTA;
- иметь заголовок и кнопку закрытия;
- закрываться по `Escape`;
- при допустимом UX закрываться по overlay;
- удерживать фокус внутри;
- возвращать фокус инициатору;
- блокировать фоновую прокрутку;
- восстанавливать прокрутку при закрытии;
- иметь `role="dialog"` и `aria-modal="true"`;
- быть связана с заголовком;
- работать на мобильном экране;
- прокручивать длинное содержимое.

Блокировка `body` допустима только как временное поведение модалки и должна гарантированно сниматься. Не используй глобальный CSS для оформления `body`.

## 22. Формы HTML On Page Lead Capture

Каждая форма заранее соответствует плагину HTML On Page 2.1.

Надёжный стандарт:

```html
<div data-lead-root>
  <form data-hop-lead-form>
    <label>
      <span>Ваше имя</span>
      <input name="name" type="text" autocomplete="name">
    </label>

    <label>
      <span>Телефон</span>
      <input name="phone" type="tel" autocomplete="tel" required>
    </label>

    <input name="contact_method" type="hidden" value="Телефон">
    <input name="quiz_service" type="hidden" value="SERVICE_NAME">

    <button type="submit" data-hop-lead-submit>
      Отправить заявку
    </button>
  </form>

  <div data-lead-success hidden>
    Заявка принята
  </div>
</div>
```

Обязательные правила:

- В момент финальной отправки внутри видимого блока заявки (`form` или `data-lead-root`) есть заполненное контактное поле: `phone` или `email`. Для dialpad допустим скрытый `input name="phone"`, синхронизированный с видимым вводом телефона внутри того же блока.
- Каждое передаваемое поле имеет `name`.
- Используй стандартные имена `name`, `phone`, `email`, `contact_method`.
- Ответы скрываемых шагов квиза дублируй отдельными именованными полями внутри финальной формы, включая `contact_method`; одного JSON-поля с ответами недостаточно.
- Radio и checkbox имеют реальные `name` и `value`.
- Финальная кнопка — `button type="submit"` либо `button type="button" data-hop-lead-submit`.
- Финальная кнопка не является ссылкой.
- Если показываешь success-экран, можно дополнительно пометить его `data-lead-success`; показывай его только после подтверждённой отправки.
- Поля не очищаются до отправки и success-состояния.
- Закрытие модалки не очищает введённые контакты и ответы квиза.
- Если плагин должен игнорировать форму, пометь её `data-lead-ignore`.
- Ошибка не удаляет введённые данные.
- Повторная отправка блокируется на время обработки.
- Используется утверждённый текст согласия на обработку данных.

## 23. Локальное поведение форм

В локальном файле плагина нет. В Astro dev допускается только локальная проверка без отправки и без success-экрана. Добавляй `data-lr-demo-form="true"` при `import.meta.env.DEV`; в production-разметке атрибута быть не должно. Для HTML On Page `formAction` не обязателен; он нужен только при отдельной отправке на согласованный endpoint.

```js
const forms = root.querySelectorAll('form[data-lr-demo-form="true"]');

forms.forEach((form) => {
  form.addEventListener('submit', (event) => {
    event.preventDefault();
    if (!form.reportValidity()) return;

    const message = form.querySelector('[data-lr-form-message]');
    if (message) message.textContent = 'Локальная проверка пройдена. Заявка не отправлена.';
  });
});
```

Не создавай фиктивный сетевой запрос и не отправляй данные на сторонний endpoint.

## 24. Квизы

- Один шаг содержит один ясный вопрос.
- Варианты имеют `name`/`value`.
- Ответы сохраняются при переходе назад.
- Промежуточная кнопка не отправляет заявку.
- Контактный шаг отделён от информационных.
- Финальная отправка происходит один раз.
- Квиз доступен с клавиатуры.
- Прогресс отображается честно.
- Ответы синхронизируются с реальными полями внутри `data-lead-root`.

Для квиза без `form`:

На финальном шаге показывай контактный ввод внутри `data-lead-root`. Для кнопки `type="button"` проверяй заполнение и корректность контакта до отправки: `required` сам по себе её не блокирует.

```html
<div data-lead-root>
  <label>
    <span>Телефон</span>
    <input name="phone" type="tel" autocomplete="tel" required>
  </label>
  <button type="button" data-hop-lead-submit>Получить расчёт</button>
</div>
```

Не используй `.lr-btn[type="button"]` на промежуточной кнопке, если она не должна инициировать заявку: текущий мост плагина рассматривает такой селектор как потенциальную отправку. Используй отдельный класс вроде `.lr-quiz-control`.

## 25. Мобильный нумпад

На планшетах и мобильных устройствах:

- по LR-стандарту поле имени скрывается, если ТЗ явно не требует обратного;
- телефон вводится через адаптивный цифровой интерфейс;
- значение синхронизируется со скрытым `input name="phone"`;
- визуальный дисплей не является единственным источником данных;
- доступно удаление цифры;
- используется та же валидация телефона;
- интерфейс имеет отступы от краёв;
- длинная модалка прокручивается;
- полоса может быть скрыта, но прокрутка остаётся;
- сохраняется доступный клавиатурный или нативный fallback.

```html
<div class="lr-dialpad__display" aria-live="polite">+7 (999) 123-45-67</div>
<input name="phone" type="hidden" value="+79991234567">
```

## 26. Доступность

- Обеспечь видимый `:focus-visible`.
- Не удаляй outline без равноценной замены.
- Проверь контраст.
- Не передавай смысл только цветом.
- Все действия доступны с клавиатуры.
- У icon-only кнопки есть доступное имя.
- Декоративная иконка скрыта от screen reader.
- Ошибка формы связана с полем.
- Динамическое сообщение использует live region.
- Учитывай `prefers-reduced-motion`.
- Страница остаётся понятной без анимации.

## 27. Локальная проверка

Открывай страницу через локальный HTTP-сервер, а не только через `file://`, потому что некоторые браузерные ограничения отличаются.

Допустимые примеры:

```powershell
python -m http.server 8080
```

или любой эквивалентный статический сервер среды.

Проверь минимум:

- 360 px;
- 390 px;
- 768 px;
- 1280 px;
- 1440 px.

Проверь:

- открытие страницы;
- отсутствие горизонтального скролла;
- порядок и читаемость секций;
- все локальные медиа;
- все CTA и ссылки;
- модалки, Escape и focus trap;
- формы и локальную проверку без отправки;
- мобильный нумпад;
- квиз и возврат назад;
- CDN-библиотеки;
- Console без ошибок;
- Network без 404;
- отсутствие запросов к неутверждённым внешним доменам.

## 28. Проверка изоляции

Для локального теста добавь временный контрольный элемент вне `#hop-landing` либо используй отдельную тестовую оболочку:

```html
<div class="wp-environment-test">
  Контрольный элемент вне лендинга
</div>
```

Сымитируй конфликтные правила Themeco:

```css
.entry-content h1 { color: #333; font-family: serif; }
.entry-content p { color: #444; }
.entry-content button { border-radius: 0; }
```

Убедись, что:

- лендинг сохраняет свой дизайн;
- собственные стили не меняют контрольный элемент;
- модалки находятся выше условного хедера;
- удаление тестовой оболочки не меняет работу лендинга.

Не оставляй тестовые стили и контрольный элемент в итоговом `index.html`.

Дополнительный WP-промпт впоследствии должен:

9. Создать итоговый HTML-фрагмент.

Не выполняй эти девять действий на текущем этапе.

## 34. Главный принцип

Создай локальный HTML-комплект, который уже выглядит и ведёт себя как финальный лендинг, но остаётся безопасным промежуточным продуктом:

- локальные медиа;
- полноценная HTML-обёртка для preview;
- полная CSS/JS-изоляция;
- готовые формы плагина;
- никакой публикации;
- минимальная и предсказуемая последующая WP-обработка.

Не жертвуй качеством дизайна, доступностью или корректностью ради того, чтобы раньше времени имитировать финальную загрузку в WordPress.
