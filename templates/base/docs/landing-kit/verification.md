# Проверка и сдача

<a id="verification"></a>

## Проверка качества

### Статическая проверка

- При установке используй зафиксированный lock-файл.
- Запусти `npm run quality` и убедись, что сборка прошла.
- В исходниках нет очевидных битых импортов.
- Нет неиспользуемых обязательных зависимостей.
- Нет секретов, абсолютных локальных путей и debug-кода.
- Нет глобальных CSS-селекторов за пределами разрешённого контракта.
- Все собственные классы имеют `lr-`.
- Все формы имеют корректные `name` и финальные кнопки.

### Браузерная проверка

Используй размеры брифа. Если они не заданы, для полной приёмки проверь 360, 390, 768, 1280 и 1440 px, для локального изменения — 390 и 1440 px и точки смены затронутой вёрстки. Сравнивай перенос с оригиналом на тех же ширинах. Проверь применимые к задаче состояния:

- соответствие утверждённой композиции;
- отсутствие горизонтального скролла;
- читаемую типографику;
- порядок контента;
- CTA и ссылки;
- формы и ошибки;
- квиз и возврат по шагам;
- модалки, overlay и Escape;
- focus trap и возврат фокуса;
- Swiper и GLightbox;
- мобильный ввод телефона;
- success-состояния;
- отсутствие ошибок консоли;
- отсутствие 404;
- отсутствие воздействия на тестовые элементы вне `#hop-landing`.

### Контроль Themeco

Если доступен локальный стенд совместимости, вставь лендинг в оболочку, имитирующую `.entry-content` и типовые глобальные стили Themeco. Это не тест WordPress, а проверка устойчивости HTML-фрагмента к окружающему CSS.

## Доступность

- Обеспечь видимые `:focus-visible` состояния.
- Не удаляй outline без полноценной замены.
- Проверяй контраст текста, кнопок и полей.
- Не передавай смысл только цветом.
- Все функции доступны с клавиатуры.
- У иконок-кнопок есть доступное имя.
- Декоративные иконки скрыты от screen reader.
- Ошибка формы связана с соответствующим полем.
- Динамические сообщения озвучиваются через подходящий live region.
- Анимация учитывает `prefers-reduced-motion`.
- Интерфейс остаётся понятным при отключённых декоративных эффектах.

## Производительность

- Не добавляй библиотеку ради одного простого эффекта.
- Не загружай неиспользуемые начертания шрифта.
- Не загружай desktop-изображение на мобильном, если доступен существенно меньший вариант.
- Не делай тяжёлое видео обязательным для понимания первого экрана.
- Минимизируй layout shift.
- Не выполняй тяжёлые циклы и измерения layout на каждом scroll event.
- Используй `requestAnimationFrame`, IntersectionObserver и пассивные обработчики там, где это уместно.
- Не добавляй преждевременную сложную оптимизацию без измерения.
- Проверяй отсутствие 404 и повторных загрузок ресурсов.

## Отчёт о сдаче

Назови результат и затронутые файлы. Для каждой фактической проверки укажи команду или сценарий, ширину экрана при проверке в браузере и наблюдаемый результат. Отдельно перечисли открытые дефекты и пропущенные проверки. Если упала сборка, есть ошибка в консоли или появилась утечка стилей, зафиксируй причину и исправь её в пределах затронутого компонента.
