# Формы, телефон и квизы

<a id="lead-capture"></a>

## Формы и Lead Capture

Формы проектируй под мост HTML On Page Lead Capture даже на стадии локальной Astro-разработки.

Надёжный стандарт:

```html
<div data-lead-root>
  <form data-hop-lead-form>
    <label>
      <span>Ваше имя</span>
      <input name="name" type="text" autocomplete="name" />
    </label>

    <label>
      <span>Телефон</span>
      <input name="phone" type="tel" autocomplete="tel" required />
    </label>

    <input name="contact_method" type="hidden" value="Телефон" />
    <input name="quiz_service" type="hidden" value="Название услуги" />

    <button type="submit" data-hop-lead-submit>Отправить заявку</button>
  </form>

  <div data-lead-success hidden>Заявка принята</div>
</div>
```

Обязательные правила:

- В момент финальной отправки внутри видимого блока заявки (`form` или `data-lead-root`) есть заполненное контактное поле: `phone` или `email`. Для dialpad допустим скрытый `input name="phone"`, синхронизированный с видимым вводом телефона внутри того же блока.
- У каждого отправляемого поля есть `name`, а не только `id`.
- Используй стандартные имена: `name`, `phone`, `email`, `contact_method`.
- Ответы скрываемых шагов квиза дублируй отдельными именованными полями внутри финальной формы, включая `contact_method`; одного JSON-поля с ответами недостаточно.
- Для вариантов квиза используй корректные пары `name`/`value`.
- Для группы checkbox допускай `services[]` или другое осмысленное имя массива.
- Финальная кнопка — `button type="submit"` либо `button type="button" data-hop-lead-submit`.
- Не используй ссылку как финальную кнопку.
- Если показываешь success-экран, можно дополнительно пометить его `data-lead-success`; показывай его только после подтверждённой отправки.
- Не очищай поля до отправки и фиксации success-состояния.
- Закрытие модалки не очищает введённые контакты и ответы квиза.
- Если плагин должен игнорировать форму, пометь её `data-lead-ignore`.
- Не показывай успех при проваленной локальной валидации.
- Предотвращай повторные нажатия во время обработки.
- Сохраняй введённые данные при исправлении ошибки.
- Добавляй обязательное согласие на обработку персональных данных, если оно требуется утверждённым юридическим текстом.

Для кастомного квиза без `form`:

На финальном шаге показывай контактный ввод внутри `data-lead-root`. Для кнопки `type="button"` проверяй заполнение и корректность контакта до отправки: `required` сам по себе её не блокирует.

```html
<div data-lead-root>
  <label>
    <span>Телефон</span>
    <input name="phone" type="tel" autocomplete="tel" required />
  </label>
  <button type="button" data-hop-lead-submit>Получить расчёт</button>
</div>
```

Не используй на промежуточных кнопках селекторы, которые плагин считает отправкой. В частности, не назначай обычной навигационной кнопке одновременно `.lr-btn` и `type="button"`, если она не должна инициировать заявку. Для переходов квиза используй отдельный нейминг и проверяй фактическое поведение моста.

Локальный обработчик проверки формы подключай только к `data-lr-demo-form="true"`, который Astro добавляет при `import.meta.env.DEV`. В production-разметке этого атрибута нет: локальный обработчик не перехватывает отправку плагином. В dev показывай сообщение «Заявка не отправлена», не success. Для HTML On Page `formAction` не обязателен; он нужен только при отдельной отправке на согласованный endpoint.

## Мобильный ввод телефона

Для форм Lenremont на планшетах и мобильных устройствах предусматривай мобильный режим:

- по текущему LR-стандарту поле имени скрывается; оставляй его только по прямому требованию ТЗ;
- телефон вводится через адаптивный цифровой интерфейс;
- фактическое значение всегда синхронизируется со скрытым `input name="phone"`;
- визуальный дисплей не является единственным источником значения;
- интерфейс не прилипает к краям экрана;
- длинная модалка прокручивается;
- скрытая полоса прокрутки не должна отключать саму прокрутку;
- доступна коррекция введённой цифры;
- значение проходит ту же валидацию, что обычное поле телефона;
- должна сохраняться возможность доступного ввода с клавиатуры или нативного поля, если кастомный интерфейс недоступен.

Пример синхронизации:

```html
<div class="lr-dialpad__display" aria-live="polite">+7 (999) 123-45-67</div>
<input name="phone" type="hidden" value="+79991234567" />
```

## Квизы

- Каждый шаг имеет ясный вопрос и понятные варианты.
- Текущее состояние хранится предсказуемо и отражается в реальных полях формы.
- Выбранные варианты имеют `name` и `value`.
- Пользователь может вернуться назад без потери ответов.
- Промежуточный переход не считается заявкой.
- Контактный шаг отделён от информационных шагов.
- Финальная отправка происходит один раз.
- Квиз работает с клавиатуры.
- Прогресс не должен вводить пользователя в заблуждение.
- Success-экран показывается только после корректного завершения сценария.
