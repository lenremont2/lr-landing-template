# Pi в проекте Landing Kit

Из корня проекта запусти установленный Pi с настроенной моделью.

```sh
pi
```

На первом запуске подтверди доверие проекту, чтобы Pi обнаружил локальные скиллы в `.agents/skills/`. Затем дай обычную задачу, например «Добавь на лендинг секцию с этапами работы и проверь сборку». Pi получает [AGENTS.md](../AGENTS.md) при запуске и по нему находит [рабочий процесс](landing-workflow.md).

Общие правила проекта добавляй в [AGENTS.md](../AGENTS.md). Выбор скиллов и переходы меняй в [рабочем процессе](landing-workflow.md). Для повторяемого приёма создай `.agents/skills/<имя>/SKILL.md` с полями `name` и `description` и опиши, когда применять скилл, что прочитать, сделать и проверить.

## Настроить под проект

Например, для страницы с согласованным планшетным макетом запиши в бриф ширину 1024 px. Она войдёт в приёмку этой страницы. Общий маршрут сдачи хранится в рабочем процессе.

Для регулярной сверки прайсов добавь `.agents/skills/lr-price-table/SKILL.md`. Имя в метаданных — `lr-price-table`, описание — «Сверяет строки, единицы и условия цен с утверждённым прайсом». В теле укажи, какой источник прочитать и как проверить итоговые строки. Перезапусти Pi. Проверь обычными запросами «обнови цены по прайсу» и «увеличь шрифт в таблице цен». Для новой самостоятельной работы добавь строку в карту маршрутов.

При обновлении существующего лендинга команда `update` обновляет [оглавление справочника](MASTER_DEVELOPMENT_PROMPT.md) и его главы в `docs/landing-kit/`. Правила конкретной страницы храни в брифе или `AGENTS.md`. Маршрут и скиллы принадлежат проекту. Сравни их с чистым проектом нужной версии и перенеси выбранные изменения.
