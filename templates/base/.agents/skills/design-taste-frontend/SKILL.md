# Taste для лендинга

Этот профиль использует локальные инструменты Taste для выбора направления и браузерной проверки. Пакет содержит исходные скрипты и лицензию Taste.

1. Прочитай бриф и зафиксируй основное действие. Найди принятые элементы бренда, существующие компоненты и реальные доступные материалы. Для точной реализации референса следуй референсу. Для существующего утверждённого дизайна используй его язык через [project-ui](../project-ui/SKILL.md).
2. При новом направлении предложи три варианта композиции с помощью [draw.mjs](scripts/draw.mjs) или сформулируй варианты самостоятельно, если скрипт недоступен. Передай роли секций из брифа явно, без роли `footer`. Сравни варианты по тому, как они показывают содержание и действие, затем выбери один для реализации. Зафиксируй выбор и причины в существующих дизайн-заметках или `docs/design.md`.
3. Дай странице одну выразительную композицию первого экрана, ясную иерархию текста, согласованный ритм секций и подходящее изображение или содержательную визуализацию по теме. Сделай соседние секции различимыми по композиции. Сохрани ограничения бренда и фактов. Изображения бери из проекта либо используй разрешённые материалы с указанным происхождением. Сгенерированное или стоковое изображение описывай как иллюстрацию. Для найденных изображений есть [assets.mjs](scripts/assets.mjs). Сохраняй выбранные медиа в `public/media`. Проверь каждое фото рядом с текстом блока по правилам project-ui. Если снимок ничего не объясняет в этом месте, пересмотри его назначение.
4. Перед реализацией зафиксируй, как выбранное направление влияет на первый экран, порядок или ритм секций и использование изображений. Через project-ui реализуй решение в существующем стеке. Открой снимки страницы на размерах из брифа, а если они не заданы — на 390, 768 и 1440 px. По снимкам оцени ясность заголовка и действия, уместность визуала, композицию и читаемость. Исправь заметные проблемы и повтори проверку затронутых состояний. Клавиатурный фокус и переход по CTA проверь в браузере.

Запусти команды из корня проекта. Подбери параметры под бриф и повтори запуск `draw.mjs` с `--direction <id>` вместо `--options 3`, чтобы сохранить выбранный вариант. `TASTE_SKILL_HISTORY` задаёт файл истории внутри проекта. В Bash используй `export TASTE_SKILL_HISTORY=.taste-skill/history.json`.

```powershell
$env:TASTE_SKILL_HISTORY = '.taste-skill/history.json'
node .agents/skills/design-taste-frontend/scripts/draw.mjs --sector other --brief "Ремонт телевизоров ЛЕНРЕМОНТ" --sections hero,list,pricing,how-it-works,faq,cta --options 3
```

После успешной сборки запусти [inspect.mjs](scripts/inspect.mjs) из `dist/`, чтобы локальные пути начинались от корня сборки. Нужен установленный Chrome, Edge или Chromium.

```powershell
Push-Location dist
node ../.agents/skills/design-taste-frontend/scripts/inspect.mjs index.html --widths 1440,768,390 --out ../.taste-skill/final
Pop-Location
```

Если бриф предполагает спокойную страницу без анимации, используй `--allow still-page`. Остальные замечания инспектора сверяй с фактической страницей. Сверку композиции и исправлений запиши в дизайн-заметки. Для подробной оценки используй [critique.md](references/critique.md). Если запуск браузера или просмотр изображений недоступен, сохрани доступные измерения и назови конкретное ограничение.
