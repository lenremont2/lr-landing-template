# Создавать проект в текущей папке и безопасно обновлять инфраструктуру

Команда `landing-kit create .` создаёт проект непосредственно в текущем пустом
каталоге. Имя npm-проекта определяется по имени этого каталога и проходит ту же
валидацию, что и явно указанное имя. Запрет записи в непустую целевую папку и
отсутствие `--force` сохраняются. Существующий пустой текущий каталог не
удаляется и не заменяется, чтобы родительский PowerShell на Windows не блокировал
операцию.

Команда `landing-kit update` запускается только из корня проекта, в
`devDependencies` которого присутствует `@lenremont/landing-kit`. До любых
изменений команда обязательно запрашивает подтверждение `(y/N)`. Ответ `n` или
пустой ответ отменяет операцию без записи файлов.

После подтверждения обновляется только управляемая инфраструктура: `AGENTS.md`,
`.gitignore`, каталог `docs`, конфигурации Astro, Prettier и TypeScript, а также
стандартные scripts, engines и точные версии devDependencies в `package.json`.
Пользовательские поля `package.json` объединяются с управляемыми и сохраняются.

Каталоги `src` и `public` не читаются как источник обновления и не
перезаписываются. Поэтому страницы, компоненты, стили, JavaScript и медиа
конкретного лендинга остаются неизменными. По умолчанию после обновления
выполняется `npm install`; флаг `--no-install` откладывает этот шаг.

Решение не добавляет WordPress-экспорт, публикацию, учётные данные, API или код
плагина.
